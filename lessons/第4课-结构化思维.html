01

为什么你说不清楚

不是嘴笨，是信息没排队

说不清的根源，往往不是表达能力，而是脑子里的信息是一团乱麻：点很多，但谁也不挨着谁。开口时只能想到哪说到哪，对方听着累，你也越说越没底。

结构化思维干的事只有一件：在开口之前，先把脑子里的信息排好队、分好堆、码成塔。嘴只是执行者，脑子码好了，嘴自然顺。

练一练：点开看看这些"说不清"，病根是哪个

乱想到哪说到哪

点开看病根

没有结论。对方听了三分钟，还不知道你要干嘛、想让他做什么。

乱所有事一样重要

点开看病根

没有主次。关键信息被埋在细节堆里，领导抓了半天才抓到重点。

乱分类全凭感觉

点开看病根

没有分组。同一件事在报告里出现了三次，另一件关键的事压根没提。

乱越想越绕

点开看病根

没有顺序。讲完原因想起了补充，补充完又绕回开头，听众跟着你迷路。

结论：说不清楚 ≠ 嘴笨。是信息在你脑子里没有"排队"。这节课就是给你一套排队方法。

02

金字塔四原则

结论先行 · 以上统下 · 归类分组 · 逻辑递进

结构化思维的成品是一座金字塔：塔尖是结论，塔身是支撑结论的几组理由，塔基是具体的事实和数据。四条原则管住这座塔。

1结论先行开口先给答案，再补理由›

先说结论，再说为什么。对方的大脑最想要的就是"你到底想说什么"——你把它藏在最后，等于逼对方边听边猜。

例：先说"建议延期一周上线"，再讲三条原因。而不是从"上周二我们开了个会"开始讲。
2以上统下上一层是下一层的概括，下一层撑住上一层›

塔尖那句话，下面每组理由都必须能"撑住"它。撑不住的内容，要么删掉，要么别往这层放。

例：结论是"延期一周最稳"，下面每组理由都得回答"为什么要延期"。突然冒出来的"顺便说个设计细节"，就是不统下的垃圾信息。
3归类分组同一层按同一类归堆，一次记一组›

十个杂点直接扔出去，谁都记不住。归成三组、每组起一个小标题，听众一次记一组——负担降了一大半。分组的规矩是 MECE，下一节细讲。

例：十条延期原因，归成"环境、人力、需求变动"三组，比平铺十条清楚十倍。
4逻辑递进同组之内按顺序排：时间 / 结构 / 重要性›

同一组的几条理由，排好顺序：按时间先后、按空间结构、或按重要性从大到小。顺序一乱，逻辑就断，听众开始自己脑补衔接。

例：讲排障按"先易后难、先外围后核心"排，而不是想到哪个讲哪个。

口诀结论先行先开口，上面统着下面走；归类分组不重不漏，同组之内排好顺序。

03

两个工具：MECE 与 SCQA

分组要不重不漏，开场要四步抓人

搭金字塔时有两个最好用的工具：MECE 管分组，SCQA 管开场。

MECE（读作"麦西"）：相互独立，完全穷尽。翻成人话——组和组之间不重叠，所有组合起来不遗漏。重叠就是重复汇报，遗漏就是拍脑袋。

重叠两个组说的是同一件事

点开看例子

把"测试没做完"和"环境没就绪"分成两组——这俩其实是一回事的两种说法。领导听两遍等于信息为零，还觉得你思路不清。

遗漏关键那一类压根没进塔

点开看例子

排障只查了应用日志，没查网络和依赖服务——分组看着整齐，关键那一类根本不在塔里。结论再漂亮也是漏的。

对照看：同一件事——项目要延期，向老板汇报，两种说法切一下

你
"那个……昨天线上又出了个小问题，后来测试那边说用例跑不完，我最近一直在协调环境，还有客户那边一直在催交付……"
开口没有结论，先讲流水账。老板前三句就开始猜：他到底想说啥？
你
"……对了上周那个接口联调也卡住了，我在想要不我们再看看排期，反正现在这样下去也不行，您觉得呢？"
细节堆成一团，"您觉得呢"把决策甩了回去——老板还要帮你理信息。
结果：老板听完只记得"出了一堆事"，结论、请求、下一步全没有。你还花了两分钟。
你
S 情境："项目按计划，月底联调。"
先共识：说一个对方肯定点头的背景，建立共同起点。
你
C 冲突："但关键接口联调被阻塞，测试环境这周还没就绪。"
再转折：变化出现了，原来的计划保不住了——对方开始关心。
你
Q 问题："原计划还守不守得住？"
把冲突变成一个明确问题，替对方把心里的疑问说出来。
你
A 答案："我的建议是延期一周上线。我已经列好了这一周补回进度的三件事。"
最后给答案：结论先行落在这里，而且带着方案，不是抛问题。
结果：四句话、一分钟以内。老板知道了结论、理由和你的请求，只需要拍板。

差异说明：混乱版是"想到哪讲到哪"，SCQA 版是"先共识背景 → 再打破它 → 替对方提出疑问 → 最后给答案"。四步走完，对方的脑子已经被你铺好路，答案自然落进去。

04

三个实战场景

汇报倒着讲 · 方案正着拆 · 排障沿着剪
1电梯汇报30 秒，在电梯里说清一件事›

只有 30 秒时，别按时间顺序讲过程。按金字塔倒着讲：先结论，再三条理由，最后一句你要对方做什么。

例（示意）：电梯里遇到老板，30 秒版——"建议项目延期一周上线（结论）。原因三条：环境未就绪、联调阻塞、用例积压（分组）。需要您批一周缓冲（请求）。"说完正好到站。
2方案拆解把一个大方案，铺成可执行的层级›

拿到一个大目标，先写塔尖一句话，再往下拆三层：目标 → 三个支撑方向 → 每个方向的具体动作。拆完用 MECE 自查：三组之间有没有重叠？合起来够不够覆盖目标？

例（示意）：塔尖"提升注册转化率" → 三个方向：落地页、注册流程、新客激励 → 每个方向下面挂具体动作清单。上一层是概括，下一层撑得住。
3议题树排障逐层定位线上问题 / 业务问题›

出了问题别一上来就猜。从顶层问题往下拆：问题是什么？可能的大类有哪些？每一类怎么快速验证？排除掉一类，就少一个方向，直到卡住某一类再往下钻。

例（示意）：顶层"接口变慢" → 拆成四类：客户端、网络、服务端、数据库 → 先看监控排除最不可能的两类 → 剩下"服务端"再往下拆成具体接口、线程池、慢查询。议题树逼你按顺序验证，而不是东一榔头西一棒槌。

三个场景，同一座金字塔：汇报是倒着讲（从上往下），方案是正着拆（从尖到基），排障是沿着树逐层剪（排除法）。

05

自测：五道题

答对 4 题，这课就过
1. 金字塔四原则是哪四个？
塔尖结论先行，以上统下管住层级，归类分组管住同层，逻辑递进管住顺序。
2. MECE 说的是什么？
相互独立（不重叠）、完全穷尽（不遗漏）。重叠是重复汇报，遗漏是拍脑袋。
3. SCQA 里的 C 指的是？
S 情境 → C 冲突 → Q 问题 → A 答案。冲突就是那个"原来的计划保不住了"的转折。
4. 电梯里只有 30 秒，汇报第一句应该说什么？
时间越短，越要结论先行。先给答案，再补三条理由和一个请求。
5. 用议题树排障，正确打法是？
先分类、再验证、排除掉不对的方向，最后卡在某一类再往下钻——这就是议题树。
