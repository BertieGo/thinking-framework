01

三种树：拆开问题的三把刀

同一个问题，三种拆法

面对一团乱麻，第一反应是"我该从哪下手"。答案不是凭感觉挑一个方向，而是选对一种拆法。常用的就三种：议题树、假设树、是否树。点开看区别。

议题树

Issue Tree · 拆问题
把一个大问题逐层拆成子问题："延期"拆成需求、开发、测试三块，每块再往下拆。它回答"这个问题可以分成哪些部分"。适合：完全陌生的问题，先找全分析角度，不漏。

点开看怎么用

假设树

Hypothesis Tree · 押答案
先押一个假设："延期是测试环境不够导致的"，再往下拆"如果它成立，我应该看到什么证据"。证据支持就深入，不支持就换假设。适合：已有方向、要快速验证，不绕弯路。

点开看怎么用

是否树

Yes / No Tree · 做排查
每个节点是一道判断题，用"是 / 否"一条路一条路分流："复现了吗？→ 有日志吗？→ 是配置问题吗？"。它回答"现在该走哪条路"。适合：排查故障、一步步收敛答案。

点开看怎么用

怎么选：问题完全陌生 → 议题树先铺开；心里有个怀疑对象 → 假设树去验证；情况二选一、要快速定位 → 是否树做排查。拆错树，比不拆还耽误事。

02

5Why 与鱼骨图：问到根上

现象不是原因，中间层也不是

拆树解决"面"的问题：保证角度全。但每个分支里为什么会这样，要靠纵向追问——这就是 5Why。另外，人脑找原因容易盯着最近那一件事漏其他维度，鱼骨图用固定维度帮你防漏。

鱼骨图的六个固定维度：别只盯"人"，把这六格过一遍

人 · 谁在做、能力够不够 机 · 工具、设备、环境够不够 料 · 输入物、数据、材料对不对 法 · 流程、方法、规范合不合理 环 · 现场约束、时间、外部条件 测 · 怎么发现的、标准是什么

用法很朴素：原因出来后，扫一眼这六格——是不是只查了"人"？"机"和"法"看了吗？大多数漏判，都漏在没扫这六格。

5Why 拆解器：追五层，看根因长什么样

先写下一个真实问题，然后一层一层追"为什么"。每层填完答案，点「再追一层」。注意：第一层答案通常不是根因——它只是下一层问题的入口。

已经追了 0 层。一般追到 3-5 层、答案落到"能动手改"的那一层，就停。

关键认知：5Why 不是"必须问满五次"，是问到答案能变成行动为止。问一层就说"根因找到了"，多半是把中间层当结论——这是高频错误，下一节细讲。

03

经典框架的底层密码：MECE

3C、SWOT、五力为什么是它们

3C、SWOT、波特五力，这些框架看起来各不相同，底层是同一个动作：把影响结果的变量，按同一维度切成不重叠的几块，合起来又盖全。这个动作有个名字——MECE（Mutually Exclusive, Collectively Exhausted）：相互独立，完全穷尽。

框架它在分什么
3C一个生意的处境：公司自己（Company）× 客户要什么（Customer）× 对手在做什么（Competitor）
SWOT一个选择的条件：内部两面（优势 S / 劣势 W）× 外部两面（机会 O / 威胁 T）
波特五力一个行业的赚钱难度：现有竞争 × 新进入者 × 替代品 × 供方议价 × 买方议价

为什么它们管用：你自己拆，容易"重一块、漏一块"——重了等于白分析两遍，漏了等于在盲区里做决策。这些老牌框架，本质是前人替你把"不重不漏"这件事做完了。学框架不是背名词，是借他们切好的那把刀。

04

没有现成框架时：自己造一个

列全 → 分组 → 校验 → 命名

现实问题很少正好落在 3C 或 SWOT 里。但造一个自己的框架并不玄，就四步。点开看每步做什么。

1列全变量先不管分类，想到什么写什么›

拿张纸，把跟这个问题沾边的所有因素一口气写下来，这一步禁止分类、禁止评价。分类会让你边写边丢。目标只有一个：不漏。

例："为什么线上报错变多"——写：人累、发布急、监控少、测试覆盖低、最近换了组件、日志没接、新人不熟、回滚慢……先全倒出来。
2按同一维度分组问一句：这些事是同一层的吗›

把倒出来的东西归类。分组的尺子要同一把：按"谁的环节"分，就全按环节分；按"内部外部"分，就全按内外分。一把尺子分到底，组间才不会重叠。

例：上面那堆，按"人 / 流程 / 工具 / 环境"分：人累、新人不熟 → 人；发布急、回滚慢 → 流程；监控少、日志没接 → 工具；换了组件、测试覆盖低 → 环境与输入。
3MECE 校验两两看重不重，合起来看漏不漏›

两两检查：有没有两件事其实说的是一块？再整体扫一遍：刚才列全的变量，有没有哪个没进组？有重叠就合并，有漏就补组。这步是框架和"随便分堆"的分界线。

例："测试覆盖低"放进"环境与输入"有点勉强——它其实是"质量环节"。于是补一组，变成：人 / 流程 / 工具 / 质量 / 环境。重叠消失，组也盖全了。
4命名成型每组起个短名，下次直接套›

给每组一个两三个字的名字，你的私人框架就有了。下次遇到同类问题，不用重新拆，直接按这几组挨个过。框架是复用出来的，用三次，它就长在你脑子里了。

例：这就是为什么资深工程师排查故障快——他脑子里已经有一棵自己的"故障树"，不用每次从零开始拆。
05

五个坑，和四条检验标准

拆错了比不拆更糟

拆开一棵树很容易，拆对很难。下面五个坑都很眼熟，点开看各自怎么破。

1框架套错对象拿战略工具去查故障›

用 SWOT 分析"为什么线上报错"，或者用五力分析"明天先做哪件事"。每个框架有它的适用对象，拿错刀就切不动菜。

破法：动框架前先问：我现在要回答的是"处境判断"还是"根因排查"还是"决策分流"？根因用 5Why / 鱼骨，定位用是否树，处境才用 3C / SWOT。
2漏分支拆到一层就停，留了盲区›

"延期"只拆了需求和开发，忘了测试、忘了发布环境。你在盲区里分析得越认真，结论偏得越稳。

破法：每拆完一层，扫一眼鱼骨六维度——人、机、料、法、环、测，哪格还没拆？
3混层级把维度和具体原因放同一层›

同一层里既有"需求"这种维度词，又有"评审会没开"这种具体事件——尺子不统一，下面越拆越乱。

破法：同一层的分支必须是同一级别的抽象。维度词只用来开层，具体原因永远放在再下一层。
4把假设当结论问一层就宣布根因找到›

"延期是因为人不够"——这只是第一层答案。再问：为什么人不够？为什么偏偏这时候不够？中间层当根因，整改方案必然治标不治本。

破法：每层答案都问自己一句："这个答案能直接变成行动吗？"不能，就继续追。
5为凑框架硬塞填表游戏，越填越不像回事›

SWOT 四格硬凑，两格写得很勉强；五力里有一力跟这事毫无关系。框架是工具不是考试，该改结构就改。

破法：某一格你憋了五分钟写不出东西——那不是你笨，是这个框架不适合这个问题。回到上一步，自己造一组。

拆完之后，用这四条验收你的树

① 不重

任意两个分支，合起来说的不是同一件事。重了，分析量等于白花一半。

② 不漏

所有可能的情况都被覆盖。漏了，结论是在盲区里做的。

③ 同一维度

同一层分支用同一把尺子切。混了层级，树就塌了。

④ 上下可对接

父节点 = 子节点之和；下一层拼起来，正好能回答上一层的问题。

口诀分层不混层，追问追到根；先列全变量，再按 MECE 分组。

06

自测：五道题

答对 4 题，这课就过
1. 议题树最主要的用途是？
议题树负责"铺开"：陌生问题先拆全角度。押答案是假设树，分流排查是是否树。
2. 5Why 一般追到什么程度就停？
次数不是目的。每层答案都问："它能直接变成行动吗？"不能就继续追。
3. MECE 说的是？
不重不漏是所有经典框架的底层动作。你自己拆容易重一块漏一块，所以才借框架的刀。
4. 鱼骨图"人机料法环测"六维度的作用是？
人脑找原因容易盯着最近那一件事。每拆完一层扫一遍六格，是防漏的土办法，但很好用。
5. 自创一个分析框架，第一步该做什么？
顺序是：列全 → 分组 → MECE 校验 → 命名。边写边分类会漏，先倒全再动刀。
