金字塔表达怎么说

说了十分钟，对方还在问"所以你到底想说什么？"
这节课给你一套先说结论、层层支撑的表达骨架。
结论先行 · 以上统下 · 纵向问答 · 横向并列
向 下 开 课
01

为什么你说了半天，对方还没抓住重点

不是你嘴笨，是顺序错了

同样一件事，有人三分钟让人拍板，有人讲了十分钟对方还在追问"所以呢"。差距不在口才，在信息出场的顺序。点开看看你常踩哪几个坑。

① 流水账式汇报

按时间顺序从头讲：周一开会、周二对齐、周三出问题……讲到第八分钟，对方还不知道你要干嘛。

点开看破解

破解：把最后那句结论挪到第一句。背景只留一句，当支撑，不当开场。

② 理由一堆，没有主次

一口气列五条理由，每条都讲一点。对方记不住任何一条，也不知道哪条最重要。

点开看破解

破解：塔尖结论下面最多挂三条理由，按重要性排，最重要的先说。

③ 想到哪说到哪

讲完 A 突然补 B，再跳回 C。对方得自己在脑子里拼图，拼不出来就等于没听。

点开看破解

破解：先搭骨架再填肉：按"结论—理由—事实"的层级走一遍，再开口。

④ 铺垫太长才亮观点

"这个事先说一下背景……"绕了半天才说要干嘛。听的人耐心在前三十秒就用完了。

点开看破解

破解：结论先行。对方拿到结论，再听背景才有意义；顺序反了，背景就是噪音。

一句话：听众的脑子是个"问题接收器"——你不先给结论，他就一直在猜"你到底想说啥"，后面全听不进去。

02

金字塔怎么搭：结论先行，以上统下

塔尖一句话，下面全是它的理由

金字塔原理只有两句话：结论先行——开口第一句就是你的结论；以上统下——下面每一层，都是上面那层的理由。点开三步，把它搭起来。

1结论先行第一句话，就把你的结论或建议甩出来›

开场不是"先交代背景"，而是先给答案。对方拿到结论，后面的细节才有归属；拿不到结论，细节就是噪音。

例：开口第一句："我建议排期往后挪一周，先保质量。"——而不是"这周二我们开了个会，会上……"。
2以上统下下面每一层，都必须撑得住上面那层›

上一层是"被回答的问题"，下一层是"答案"。检验标准很简单：随便挑一条理由问自己——它真的能推出上面那句结论吗？推不出，这条就是凑数的，删掉或换。

例：结论"建议后移一周"，下面两条理由："测试环境还没就绪""核心接口联调缺人"。两条都直接指向"现在上不了"，撑得住结论。
3验收你的结论：TOPS 四原则塔尖那句话，过一遍这四道关›
T 有的放矢O 统领全局P 重点突出S 有据可依

T 有的放矢（Targeted）：说的是对方关心的事，不是你想说的事。给领导讲，先想他最关心什么——进度、风险、还是钱。
O 统领全局（Over-arching）：这一句话能盖住后面所有理由，不跑偏。讲完三条理由回头看，哪条跟它没关系？那就是结构散了。
P 重点突出（Proportioned）：同层理由不超过三条，轻重分明。什么都重要 = 什么都不重要。
S 有据可依（Supportable）：每条理由后面，都站着事实、数据或案例，不是"我觉得"。

例："建议后移一周（T 领导关心进度；O 盖住两条理由；P 只讲两条；S 环境与缺人都是事实）——四关全过，这句就是合格的塔尖。"

口诀结论先行开口见山，以上统下层层可验。

03

纵向问答，横向并列

塔怎么往上搭：方向不同，规则不同

搭金字塔只有两个方向。纵向管"接得上"：你说的每一句都要正好回答对方脑子里的下一个疑问。横向管"摆得平"：同一层的几条理由，要么是一条推理链，要么是并列不重的分点。

纵纵向：问答链上一句引发疑问，下一句正好接住›

好表达像聊天：你说一句，对方心里"咯噔"冒出一个问题，你下一句就回答它。检查方法：把自己当听众，逐层往下问"为什么"，你的回答链条要正好接得上。

例："建议后移一周"→（对方：为什么？）→"测试环境没就绪"→（对方：然后呢？）→"所以这周只能先做文档，联调排到下周"。一环扣一环，对方不用猜。
演横向·演绎：大前提 → 小前提 → 结论一条推理链，环环扣死›

演绎是顺着一条公认的规则往下推：大前提人人都认，小前提是眼前事实，结论自然成立。只要大小前提都成立，结论没有争议。

例："上线前必须完成全量回归（大前提）；核心接口还没联调完（小前提）；所以本周上线风险太大（结论）。"
归横向·归纳：同层并列分点几条同类事实，共同指向同一个结论›

归纳是摆事实：几个并列的观察放一起，结论自己浮出来。同层分点要满足 MECE：相互独立、完全穷尽——不重叠、不遗漏。两条理由说的是同一件事，合并；关键情况没覆盖到，补上。

例："环境没就绪、联调缺人、关键依赖延期"——三条并列、互不重叠，共同指向"排期要后移"。这就是归纳。

用法：纵向不顺，是你答非所问，退回问答链重搭；横向不平，是分点重叠或漏项，按 MECE 合并或补全。

04

SCQA 开场白生成器

汇报开场四句排，对方一秒入戏

塔尖结论之前，先用四句话把对方"拉进来"：S 情境（大家都认的背景）→ C 冲突（打乱现状的变化）→ Q 疑问（对方心里冒出的问题）→ A 回答（就是你的塔尖结论）。填四项，一键成稿。

生成你的 SCQA 开场白

按提示填四项。S 写大家都知道的事实，C 写打破现状的那个变化，Q 写听众最关心的问题，A 写你的结论。

S
C
Q
A

为什么这样排：先给 S，对方觉得"这事我熟"，放下戒心；再给 C，他立刻紧张；Q 替他把问题说出口；A 递上答案——你的结论就变成了"他一直在等的那句话"。

05

一段完整示范

同一件事，两种说法

场景：项目排期要动，你向领导汇报。左边是本能版，右边是金字塔版。

你
"这周我们开了好几个会，先是测试那边说资源紧张，然后联调同学又提了几个问题……"
按时间顺序倒豆子，结论还没影。
你
"对了，环境那边也一直没就绪，我们只能先做文档……"
理由零散出场，对方拼不出主次。
你
"所以……您看怎么办比较好？"
把判断题甩回给领导，还替他做决定的活也没干。
结果：领导听完皱眉："所以呢？你到底想让我拍什么板？"
你
"结论先说：我建议排期后移一周，先保质量。"
塔尖先行——第一句就是结论。
你
"理由两条：一是测试环境还没就绪；二是核心联调缺两个人手。"
同层并列、互不重叠，三条以内。
你
"新排期我已经拟好了，周三前需要您拍板。"
收尾带明确的行动请求，对方知道该干嘛。
结果：领导三句话抓到重点，当场拍板，还顺手补了人手协调。

三个场景，直接套用

汇报 / 邮件 / 演讲，骨架各一张

骨架不变，装法随场景变。点开三张卡，照模板填自己的事。

汇报

当面讲 / 会议发言

① 结论：一句话建议或判断，开口就说。
② 理由：最多三条，按重要性排，每条跟一句事实。
③ 行动：结尾明确要对方做什么决定。

例："建议后移一周（结论）；环境未就绪、联调缺人（理由）；新排期周三前请您拍板（行动）。"

07

自测：五道题

答对 4 题，这课就过
1. "结论先行"的意思是？
结论先行 ≠ 只说结论。后面的理由照样要讲，只是顺序挪到后面去撑它。
2. "以上统下"指的是？
检验方法：随便挑一条理由问——它能推出上面那句结论吗？推不出就删掉。
3. 纵向问答链说的是？
好表达像聊天：你抛一句，对方心里"为什么"，你下一句接住它。
4. 归纳式分组，同层几条理由要满足？
这就是 MECE。两条理由说同一件事就合并，关键情况没覆盖到就补上。
5. SCQA 里的 C 指什么？
C = Conflict。S 是背景，C 是变化，Q 是听众的疑问，A 是你的结论。
